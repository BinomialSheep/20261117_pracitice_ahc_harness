# 研究の記録（オーケストレーター用）

オーケストレーターがラウンドごとに新しいセッションで始めるための引き継ぎ。worker の課題には、ここの得点や経緯を書かない。

- 各ラウンドの全文は `runs/R####/plan.json`（案）と `result.json`（効果）にある。ここには要点だけ書く。
- 効果（effect）は、そのラウンドのseedでの当時のbestとの対の差の平均。ラウンドが違う効果どうしは、目安としてしか比べられない。
- 更新の仕方：close の前に「ラウンド記録」に1節を足し、「次の狙い」を書き直す。昇格したら「現bestの系譜」に1行足す。

## 分かったこと

- 1ケースの上限は約 490+0.4M（M は壁の数）。理想は「1歩移動して P=4 で撃ち新しい5マス」の繰り返し（1行動あたり2.5マス）。
- 時間を伸ばした調査（R0007/A01 の系統、内部1.75秒、seed 0〜19）：4秒で+0.9、20秒で+2.1、100秒で+3.0。伸びは初期の骨格を多く試せることから来る。焼きなましが削る行動数は、時間によらず6〜7で頭打ち。壁の少ない盤面は初期解から改善しない。長い時間向けにパラメータを調整しても、別のseedでは効かなかった。
- 解の作り方は「発射の列＋LNS」が他を大きく引き離した。R0003では、ビームサーチ（R0001）との組合せや新規の構築法が −10〜−43 だった。
- R0007以降はほぼ全案が best の続きか組合せで、効果は1未満に縮んでいる。
- R0011では初期解の案が上位3つを占めた（予選 +0.75、骨格の作り方を増やす +0.44、盤面ごとに作り方を選ぶ +0.43）。探索側の変更は1.95秒版でマイナスだった（温度の自動調整 −0.24、再出発による多様化 −0.32、戦略の切り替え −0.16）。
- 前ラウンドの2位以下を新bestに組み合わせると、効果は大きく減るか負になる。R0009で+0.3〜+0.45だった6案を R0011 で組み合わせると、+0.33・+0.21・+0.08・−0.16・−0.24・−0.32 だった。特に、集団探索（現best）と役割が重なる多様化・戦略の切り替えは負になった。
- B（R0004）で、正確な挿入コスト・パスの待ちの減点・リズムから外れた発射を狙う破壊を足したが、−0.26 だった。
- 現best（R0011/A07）を seed 0〜47 で調べた（R0012の前）。壁の少ない盤面（M≦5）は下限との差が3〜7手で、M=0 の163手は最適とみてよい。壁の多い盤面（M≧18）は下限との差が25〜35手で、発射1回あたり1手を超える移動が約30手、パスが8〜16回ある。壁の多い盤面では、乱数を変えるだけで最終の行動数が±2ぶれる。
- R0012（予選が入った best が親）では、10案とも効果が −0.08〜+0.11 に収まった（標準誤差は約0.045）。初期解を足す案はほぼ0か負だった（作り方の追加 +0.005、作り方ごとの配分 −0.007、予選の段階的な絞り込み −0.03、ブロック内の撃ち方のビーム探索 −0.08）。予選が入ったので、初期解の系統は伸びにくくなったとみる。
- R0012 の上位3つは、鎖ごと動かす近傍 +0.11、壁に合わせた区切り +0.10、判断を変えない高速化 +0.095（初期候補 362→569件、反復数 約+20%）だった。後悔値つきの修復 −0.04、副次的な評価 +0.02、区間の並べ替えDP +0.01 は効かなかった。
- R0013 では10案とも有効で、効果は −0.35〜+0.10（標準誤差 約0.045）。上位2つは R0012 の上位案の組合せで、高速化 +0.10、壁に合わせた区切り +0.07 だった。R0012 で単独だったときの効果（+0.095、+0.10）が、鎖の近傍の上にほぼそのまま乗った。役割の重ならない変更は足し合わせられる。
- R0013 で、壁の多い盤面の余分な移動とパスを狙う8つの新案（近傍・破壊・探索の方式）は効かなかった。パスを減らす近傍 +0.03、安い見積もりでの足切り +0.004、集団の解どうしで違う所を壊す −0.05、追い出しの連鎖 −0.05、1手・2手の総当たり（VND）−0.14、長い移動の両端を壊す −0.18、塗り残しを罰則つきで許す探索 −0.21、SISR −0.35。近傍や破壊を足すと既存の近傍に回る反復が減り、負になりやすいとみる。
- 判断を変えない高速化は、毎回効いている（R0007 +0.65、R0010 +0.24、R0013 +0.10）。

## 次の狙い（R0014）

- 効果は1ラウンドあたり約0.1のまま。採否の誤差（標準誤差 約0.045、10候補からの選抜）と同じ程度。
- 組合せの候補：R0013/A02（壁に合わせた区切りを予選の候補に入れる）を現bestに組み合わせる。共通の祖先は R0012/A04 で、現bestとの差は高速化だけなので、衝突は小さい見込み。
- 高速化をさらに進める。現bestをプロファイルし、修復・経路の評価・撃ち方のDP・鎖の近傍で残る重い所を削る。速くなった分は予選の候補数と反復数に回る。
- R0013 で足した近傍・破壊・探索方式の8案は、パスを減らす近傍（+0.03）を除いてほぼ0か負だった（R0012 の修復・評価・並べ替えDPの3案も同様）。この系統は後回しにする。
- 初期解の系統（作り方の追加・配分・予選の作り直し・ブロック内の探索）と、温度・再出発・多様化などの調整も後回しにする。

## 運用の注意

- Codex の利用上限は `python3 scripts/codex_limits.py` で読む（読み取りだけ）。評価の時間は、Aが約27分、Bが約5分（README）。
- codex の worker は WSL の DNS 失敗で時間切れになることがある（`docs/TEMPLATE_FEEDBACK.md` の13）。止まった worker は、その時点のコードで提出扱いになる。
- codex の10体の A ラウンドで、5時間枠を約42〜45ポイント使う（R0012・R0013）。
- 採点中に環境が不調になると、TLE として記録される。R0013 ではファイルシステムの破損で、baseline と A01 が同じseed・同じ時間で TLE になり、scores.csv の末尾がヌル文字になった。ユーザーの了承を得て `evaluation` を `evaluation.broken` に移し、最初から採点し直した。baseline の TLE は、まず環境を疑う。
