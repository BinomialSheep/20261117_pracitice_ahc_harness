# 研究の記録（オーケストレーター用）

オーケストレーターがラウンドごとに新しいセッションで始めるための引き継ぎ。worker の課題には、ここの得点や経緯を書かない。

- 各ラウンドの全文は `runs/R####/plan.json`（案）と `result.json`（効果）にある。ここには要点だけ書く。
- 効果（effect）は、そのラウンドのseedでの当時のbestとの対の差の平均。ラウンドが違う効果どうしは、目安としてしか比べられない。
- 更新の仕方：close の前に「ラウンド記録」に1節を足し、「次の狙い」を書き直す。昇格したら「現bestの系譜」に1行足す。

## 分かったこと

- 1ケースの上限は約 490+0.4M（M は壁の数）。理想は「1歩移動して P=4 で撃ち新しい5マス」の繰り返し（1行動あたり2.5マス）。
- 時間を伸ばした調査（R0007/A01 の系統、内部1.75秒、seed 0〜19）：4秒で+0.9、20秒で+2.1、100秒で+3.0。伸びは初期の骨格を多く試せることから来る。焼きなましが削る行動数は、時間によらず6〜7で頭打ち。壁の少ない盤面は初期解から改善しない。長い時間向けにパラメータを調整しても、別のseedでは効かなかった。
- 解の作り方は「発射の列＋LNS」が他を大きく引き離した。R0003では、ビームサーチ（R0001）との組合せや新規の構築法が −10〜−43 だった。
- R0007以降はほぼ全案が best の続きか組合せで、効果は1未満に縮んでいる。
- R0011では初期解の案が上位3つを占めた（予選 +0.75、骨格の作り方を増やす +0.44、盤面ごとに作り方を選ぶ +0.43）。探索側の変更は1.95秒版でマイナスだった（温度の自動調整 −0.24、再出発による多様化 −0.32、戦略の切り替え −0.16）。
- 前ラウンドの2位以下を新bestに組み合わせると、効果は大きく減るか負になる。R0009で+0.3〜+0.45だった6案を R0011 で組み合わせると、+0.33・+0.21・+0.08・−0.16・−0.24・−0.32 だった。特に、集団探索（現best）と役割が重なる多様化・戦略の切り替えは負になった。
- B（R0004）で、正確な挿入コスト・パスの待ちの減点・リズムから外れた発射を狙う破壊を足したが、−0.26 だった。

## 次の狙い（R0012）

- 初期解の系統を続ける。R0011/A07（予選）は現bestに入っている。
- 組合せの候補（親は best と次のもの）：
  - R0011/A08：骨格の作り方を増やす。予選と役割が別なので足し合わせられる見込みが高い。
  - R0011/A09：作り方を盤面ごとに選び、時間を配分する。予選と時間配分の役割が重なるので、調整が要る。
  - R0011/A03：壁に合わせた骨格の区切り（R0009/A02の系統）。
  - R0011/A06：鎖ごと動かす近傍（R0009/A10の系統）。
- 予選を深める新案：見積もりを最終結果に近づける（DPの見積もりとLNS後の結果のずれを補正する）、見積もりを速くして候補を増やす、短いLNSで段階的に絞る、など。
- 温度・再出発・多様化など探索側の調整は後回しにする。
- 他候補のコードを渡せるのはAだけ。Bで深めるなら、作り方の追加や選択を文章で指示する。

## 運用の注意

- Codex の利用上限は `python3 scripts/codex_limits.py` で読む（読み取りだけ）。評価の時間は、Aが約27分、Bが約5分（README）。
- codex の worker は WSL の DNS 失敗で時間切れになることがある（`docs/TEMPLATE_FEEDBACK.md` の13）。止まった worker は、その時点のコードで提出扱いになる。
