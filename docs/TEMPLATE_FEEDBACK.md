# 雛形へのフィードバック

ahc_thin_harness の雛形作成担当に渡す、問題によらない指摘の一覧。問題固有のことは書かない。新しい指摘は末尾に足す。

## 1. 毎回読み込まれる指示ファイルに雛形作成の経緯を書かない（ユーザー指摘）

- 起きたこと：`AGENTS.md` に、エージェントの行動に関係しない記述が多く入っていた。
  - 「本バージョンにAB-MCTS/Beads/ダッシュボード/自動LLMモデル選択はない。わざと薄く保つ」のような作成経緯
  - 想定する大会区分や、限界の説明
  - CLIが既に強制しているルール
  - `cp config.example.json` から始まる実行例の全文

  AGENTS.md は毎回読み込まれるので、こうした記述はそのままトークンの無駄になる。`docs/SETUP.md` も、オーケストレーターに `docs/DESIGN.md` を読ませる手順になっている。
- 次の雛形で：AGENTS.md には、エージェントの行動を変える指示だけを書く。worker の `task.md` など、毎回読まれる他の指示も同じ。各行について「これが無いとエージェントの行動が変わるか」を確かめ、変わらない行は削るか、人間向けの文書に移す。オーケストレーターが読む文書は AGENTS.md だけで足りるようにする。
- このリポジトリでは：AGENTS.md を行動指示だけに書き直した（6.2KB → 3.5KB）。

## 2. `.gitignore` の `config.json` が `examples/toy/config.json` まで除外する（展開時に判明）

- 起きたこと：パターンがルートに限定されていないので、デモ用の設定がコミットされない。そのため clone した先で `demo` とテストが失敗する。
- 次の雛形で：`/config.json` とルートに限定する。
- このリポジトリでは：`examples/toy/config.json` を強制追加し、`config.json` 自体もGit管理にした。

## 3. `problem/tools/README.md` のプレースホルダが公式ツールのREADMEとぶつかる（展開時に判明）

- 起きたこと：AHCの公式ツールにはたいてい `README.md` が含まれる。そのため配置するとプレースホルダ（アダプタの約束事）が上書きされる。
- 次の雛形で：アダプタの約束事は `docs/SETUP.md` に書き、`problem/tools/` には何も置かない。
- このリポジトリでは：公式のREADMEを残し、アダプタの説明は `problem/tools/LOCAL_JUDGE.md` に書いた。

## 4. 公式ツールのビルド済みバイナリの置き場所が決まっていない（展開時に判明）

- 起きたこと：ラウンドのスナップショットと worker へのコピーでは `target/` が除外される。そのため `cargo build` の成果物をアダプタからそのまま使えず、置き場所とビルド手順を問題ごとに考えることになる。
- 次の雛形で：`problem/tools/bin/`（Git管理外）と、公式ツールをビルドしてそこへ置くスクリプトを雛形に含める。
- このリポジトリでは：`scripts/build_tools.sh` を追加した。

## 5. `claude` engine の既定値では worker が検証できず、隔離も効かない（展開時に判明、実機では未確認）

- 起きたこと：
  - `claude -p --permission-mode acceptEdits` だけでは Bash が許可されないので、worker がコンパイルや `quickcheck.py` を実行できない。
  - workspace を `git init` する隔離は Codex には効くが、`claude` は親ディレクトリの `CLAUDE.md` を読んでしまう。
- 次の雛形で：`--safe-mode`、`--permission-prompts none`、`--allowedTools`（quickcheck とコンパイラ）を付けた例を、実機で確かめてから載せる。
- このリポジトリでは：`config.json` に上記を設定した（まだ実行していない）。

## 6. 評価で現bestと候補の条件が揃っていない（展開時に判明）

- 起きたこと：
  - 現bestは単独で採点し、候補は並列で採点する。そのため時間いっぱい探索する解法では、CPUの取り合いの分だけ候補が不利になる。
  - 候補内のケースは逐次実行なので、1.8秒のソルバーだと1候補あたり約30分かかる。
- 次の雛形で：ケース単位で並列化し、現bestと候補を同じ並列度で混ぜて採点する。
- このリポジトリでは：未対応。並列度8で運用している。

## 7. Pythonの必要バージョンが実態と合っていない（展開時に判明）

- 起きたこと：READMEは3.11以上を求めるが、3.11固有の機能は使っておらず、3.10でも全テストが通る。要件に合わせて `.venv` を作ったので、コマンドが `python3` から `.venv/bin/python` に変わった。
- 次の雛形で：要件を実態に合わせるか、CLIの起動時にバージョンを確かめる。
- このリポジトリでは：`.venv`（3.12）を使っている。
